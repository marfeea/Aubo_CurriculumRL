- 新增 `scripts/smoke_stage1.py`：固定 L0/目标，顺序验证三种 `z`，用受控位置增量到达参考点，校验 C1 力矩阵、动作掩码、观测/奖励有限值；传入 `--output` 时输出每模式 TCP、关节、参考点和 C1 力的 JSON 轨迹，供后续路径聚类入口消费。
- 新增 `scripts/smoke_c1_collision.py`：先进行受限关节目标扫描；若未接触 C1，则仅在独立 smoke 环境中把固定基座根位姿平移至 P0 审计的玻璃包围范围附近，以物理仿真产生真实 C1 接触。脚本只读取 ContactSensor 的 `force_matrix_w`，再通过正式 `TerminationManager` 计算终止；不写入或伪造接触力、终止标志，也不改正式场景配置。

## 结果摘要

- 编译通过；纯逻辑与既有控制/资产回归为 `26 passed`。
- 全量 Python 测试随后通过：`47 passed`。Ruff 未安装（`No module named ruff`），因此未执行 Ruff 检查，未将其记为通过。
- 4 环境零动作 smoke 正常创建、reset、step 与退出；未出现 Python 异常。
- P3 专用 Isaac smoke 退出码为 0：每种路径模式的观测形状均为 `(4, 52)`，观测和奖励保持有限；L0 的纯旋转动作在实际 `processed_actions` 中为零；`direct`、`lateral_positive`、`lateral_negative` 均在 64 个策略步内到达各自不同的中段参考点；7 个 C1 传感器均输出有限的 `(4, 1, 1, 3)` force matrix。
- 施工中曾尝试在一个覆盖全部机器人刚体的 ContactSensor 上直接配置 C1 过滤。Isaac Lab/PhysX 实际报错“expected 28, found 4”，原因是其一对多过滤限制。改为 7 个单刚体传感器后，该错误不再出现，动态 smoke 正常退出。
- C1 故障注入 smoke 退出码为 0。固定 seed 的 96 个受限关节目标均未接触玻璃，随后使用第 0 个根位姿注入 `(0.70, 0.00, 0.30) m`，在第 1 个物理步由 `Link_04` 对 C1 Glass 产生 `16,516.552734375 N` 的过滤接触力。正式 `TerminationManager` 随即得到 `illegal_contact=true`、`terminated=true`；结构化结果写入被忽略的 `data/p3_c1_collision_smoke.json`。该证据确认“C1 Glass prim → 7 个传感器 → 力汇总 → 50 N 阈值 → 终止”闭环有效。
