## 根因与施工边界

原 `scripts/evaluate_stage_e.py` 在一个 Python/SimulationApp 进程内按目标关闭并重建 Manager-Based 环境；第一个目标完成后，第二次环境重建可能持续阻塞。P1 仅调整评估进程生命周期，不修改场景、Differential IK、奖励、课程转换阈值、TCP 标定或最终停靠/安全真值。

## 本批变更

- `scripts/evaluate_stage_e.py` 改为父调度器：校验 PPO checkpoint、冻结的 `VecNormalize` 与课程快照版本后，按 `seed × target_state` 顺序调度评估单元；已完成单元 JSON 可复用，缺失或无效单元自动重跑。
- 新增 `scripts/evaluate_stage_e_worker.py`：每个 worker 只创建一个 SimulationApp，固定一个 seed 与一个目标状态，完成指定 episode 数后写入原子 JSON 并退出。
- 新增 `logic/stage_e_evaluation.py`：集中 checkpoint sidecar 路径、评估矩阵、版本/结果校验和按目标聚合，保持其与 Isaac、SB3 和文件写入解耦。
- 新增 `tests/test_stage_e_evaluation.py`：覆盖 checkpoint 配套路径、去重后的评估矩阵、版本/单元不匹配拒绝和部分结果聚合。
- 子进程返回非零时，父调度器在单元目录写入 `*.failure.json`，包含 seed、目标索引、退出码与运行命令，并以非零状态结束；已成功单元不被回退。

## 保持不变的契约

- 正式评估仍冻结 PPO 与 `VecNormalize`，关闭课程切换与训练随机化，固定 `evaluation_curriculum_level=4`，逐目标设置 `evaluation_target_state_index`。
- 课程转换仍只在训练的 `curriculum_enabled=True` 路径提交 episode 到 `CurriculumController`；P1 评估不写课程窗口、不升降级、不修改 checkpoint 快照。
- TCP 标定、四目标状态、停车进入/退出距离、姿态/速度/dwell、工作空间和安全阈值继续只来自现有任务配置。
- 终局指标仍使用 SB3 auto-reset 前缓存；安全失败覆盖同一步正式成功的优先级保持不变。

## G1 结论与遗留风险

- 已满足：单 seed、四目标的评估单元连续完成并退出；每个目标均形成独立 episode 数、终止原因和误差指标；实际运行未出现原先的第二次环境重建阻塞。
- 已实现但未进行故障注入动态复验：任一 worker 失败时父调度器返回非零并指出对应 seed/目标，同时保留部分结果与失败 JSON。
- 尚未进行冷启动的第二次完整仿真复跑，因此“相同 checkpoint、seed、配置的仿真结果在确定性允许范围内一致”尚未形成独立动态证据；当前复跑只验证了已完成单元的结果复用。
- 该 checkpoint 是短程 smoke 策略，成功率为零；P1 不构成 PPO 收敛、课程有效性或正式任务性能达标的证据。
- 后续完整正式评估仍应使用多个固定 seed 与足量 episode，并在 G4 的 PPO 基线形成后解读策略指标。
