# CurriculumRL 五阶段课程训练施工计划

版本：`v0.2-plan`  
日期：2026-07-17  
状态：待施工  
事实来源：`docs/课程设计.md`、`docs/项目理解.md`、`docs/阶段D施工记录.md`、`docs/阶段E施工记录.md`、`docs/DifferentialIK课程RL_TCP停靠方案与项目迁移说明.md`

## 1. 计划目标

本计划把当前“训练管线可做极短 smoke，但尚不能按五阶段能力课程开展正式长训练”的缺口拆成可独立施工、验证和验收的批次。

最终交付应满足：

1. 从阶段 1 起固定六维 TCP 动作和完整策略观测接口；
2. 课程依次训练位置到达、位姿到达、多目标泛化、完整碰撞避障和精确停靠；
3. 每一级同时记录阶段成功与正式停车成功，不混用二者；
4. PPO、优化器、`VecNormalize`、课程状态和配置版本能够一致保存与恢复；
5. 正式评估在固定最终任务真值下覆盖全部目标、路径模式和随机种子；
6. 只有在分层门禁通过后才扩大训练范围，不用长训练替代环境、控制器或评估缺陷诊断。

## 2. 当前基线与缺口

### 2.1 已具备

- `CurriculumRL-TcpDocking-v0` 已注册为 Manager-Based 环境；
- 观测为 29 维，动作为根坐标系 `B` 下六维 TCP 增量；
- Differential IK、奖励、终止、课程窗口和 checkpoint 三件套已有实现；
- 纯逻辑测试、四环境动态 smoke、极短 PPO 和恢复训练已有通过记录；
- 当前工作站可使用 `D:\Anaconda\envs\isaaclab\python.exe` 启动 Isaac Lab。

### 2.2 阻止正式五阶段训练的缺口

- `docs/课程设计.md` 仍是设计草案，未映射为产品配置；
- 缺少路径模式 `z`、阶段 1 旋转动作掩码和模式条件下的路径约束；
- 缺少 C1/C2/C3 碰撞配置档及碰撞前净空观测；
- 缺少独立于正式停车成功的 `curriculum_success`；
- 当前 L3 与 L4 训练难度相同，随机化为空；
- 阶段 D 尚无优于零动作和随机动作的足量 PPO 基线；
- `scripts/evaluate_stage_e.py` 在同一 SimulationApp 内重建第二个环境时阻塞；
- 运动学目标不能验证真实目标扰动，TCP 偏置仍是近似标定；
- 默认 64 环境的显存占用和长时稳定性尚无验收记录。

## 3. 固定契约与兼容策略

以下内容不随课程等级改变：

| 契约 | 固定内容 |
|---|---|
| 受控实体 | `AUBObot/AUBO_E5`，末端刚体 `Flange` |
| IK 关节 | `Joint1` 至 `Joint5` 与 `Flange`；夹爪关节不进入 IK |
| 动作 | 根坐标系 `B` 下六维 TCP 增量，单策略步最大 `0.02 m / 5°` |
| 控制频率 | 仿真 `120 Hz`，decimation `30`，策略 `4 Hz` |
| 最终位置 | 进入/退出 `0.04/0.055 m` |
| 最终速度 | `0.03 m/s` |
| 最终姿态 | `10°` |
| 最终停留 | 连续 `2` 个策略步，即 `0.5 s` |
| 四元数 | `wxyz` |
| TCP 标定入口 | `configs/task.py` 中唯一参数，不复制进奖励或 IK |

### 3.1 Checkpoint 兼容决策

阶段 1 必须加入路径模式以及为后续碰撞净空预留的观测字段，因此新课程策略输入不再是当前 29 维。施工时应：

- 将新课程配置版本升级到新的主版本，例如 `curriculum-v2-*`；
- 建立新的 PPO checkpoint 谱系；
- 把现有阶段 D/E checkpoint 仅作为训练管线和性能基线，不加载为新策略权重；
- 从阶段 1 到阶段 5 保持新观测和动作形状不变，未启用字段使用零值和显式掩码；
- 恢复时严格检查配置版本、观测 schema、`VecNormalize` 和课程状态，任何一项不兼容都快速失败。

## 6. P1：正式评估运行链修复

### 6.1 根因边界

当前阻塞发生在同一 Python/SimulationApp 内关闭第一个 Manager-Based 环境后，再为第二个目标重建环境。修复应首先改变评估进程生命周期，不先修改场景或任务真值。

### 6.2 施工方案

采用“父调度器 + 单评估单元子进程”：

- 每个子进程只创建一个 SimulationApp；
- 一个评估单元固定为一个 `seed × target_state`，完成后写出独立 JSON 并退出；
- 父调度器顺序启动子进程，校验退出码、配置版本和结果完整性，再聚合总报告；
- 已完成的单元立即落盘，后续单元失败时保留部分证据；
- 支持只重跑缺失或失败单元；
- 训练随机化关闭、课程切换关闭、PPO 和 `VecNormalize` 冻结；
- 将终局缓存时序检查保留为快速失败条件。

### 6.3 预计修改

- 拆分 `scripts/evaluate_stage_e.py` 的调度与单环境评估职责；
- 可新增 `scripts/evaluate_stage_e_worker.py`；
- 新增纯逻辑测试，覆盖 checkpoint 配套路径、子任务矩阵、部分结果聚合和版本拒绝；
- 更新 `docs/阶段E施工记录.md`，记录实际复验结果。

### 6.4 验收门禁 G1

- 单种子、四目标的最小评估可以连续完成并退出；
- 任一子进程失败时总入口返回非零状态，并指出具体 seed/目标；
- 四目标均形成独立 episode 数、终止原因和误差指标；
- 评估不发生第二次环境重建阻塞；
- 相同 checkpoint、seed 和配置的重复评估结果在允许的仿真确定性范围内一致。

## 9. P4：阶段 1 基础学习门禁

### 9.1 施工内容

1. 在完全相同的环境、seed、episode 长度和统计口径下运行零动作与随机动作基线；
2. 运行至少三个固定随机种子的阶段 1 PPO 短程实验；
3. 记录学习曲线、各奖励累计值、阶段成功率、正式成功率、安全失败率、超时率、关节限位与奇异保护触发率；
4. 按路径模式分别评估成功率与轨迹簇，检查策略是否忽略 `z`；
5. 进行奖励消融时只改变辅助权重，不改变正式任务阈值；
6. 根据证据修订暂定的晋级窗口和训练预算。

### 9.2 验收门禁 G4——允许开始课程继承训练

- PPO 在多个 seed 上显示稳定学习趋势，并优于零动作和随机动作；
- 阶段成功率达到设计门槛或经数据评审后修订的门槛；
- 不存在仅总回报上升而成功率、安全率恶化的情况；
- 至少形成设计要求数量的有效路径簇，且各簇成功率和样本占比达标；
- checkpoint 三件套可独立恢复训练和固定评估；
- 4、16、32、64 环境依次完成显存与吞吐基准，正式训练环境数以实测安全值为准。

G4 通过后，项目才具备开始一次有意义的课程继承训练的条件。

- 代表性合法接触、非法接触和近碰撞样例均能区分；
- 每目标无碰撞成功率、安全失败率和超时率达到门槛；
- 不存在通过关闭整座工作站、机器人碰撞或传感器来获得的伪通过。

## 13. P8：阶段 5——最终精确停靠

### 13.1 施工前硬门禁

- 实测复核 TCP 法兰偏置 `(0.0, -0.12, 0.102) m`；
- 将标定结果只更新到 `configs/task.py`，并回归 TCP 数学、姿态和状态机；
- 使用可扰动目标或代表性物理验证确认目标位移/速度安全判定；
- 确认最终工程精度要求未严于当前统一任务真值；如需收紧，先单独评审任务契约和全部评估口径。

### 13.2 施工内容

- 继续使用 C3 和完整目标分布；
- 加强近端低速、姿态、dwell 和精度塑形；
- 保持最终成功奖励只绑定正式停车状态机；
- 记录终端误差分布、重复性、dwell 内最大速度和姿态波动；
- 保留阶段 1 至 4 的回归评估。

### 13.3 验收门禁 G8

- 总体及每目标正式成功率达到设计门槛；
- 位置/姿态准确度、重复性和动态质量达到门槛；
- 安全失败、目标扰动、越界和超时按目标独立报告；
- TCP 标定误差不再是未关闭风险；
- 前四阶段关键能力无超出允许范围的遗忘。

## 14. P9：全课程长训练与正式验收

### 14.1 训练发布条件

- G0 至 G8 全部通过；
- 课程配置不再使用 `provisional` 版本；
- 训练环境数、显存余量、吞吐和预计 checkpoint 频率已有实测；
- 运行命令明确任务、初始等级、seed、run tag、训练预算和输出目录；
- 中断恢复演练通过，恢复后等级、窗口、优化器和归一化统计一致；
- 训练与评估不会并发启动多个争用同一 Isaac KVDB 的进程。

### 14.2 正式训练矩阵

- 至少三个训练随机种子；
- 每个 seed 保存模型、优化器、`VecNormalize`、课程状态、环境配置、agent 配置和命令；
- 每次等级切换记录旧/新等级、有效 episode 数、成功率、安全失败率、冷却状态和原因；
- 周期 checkpoint 执行小规模固定回归，最终 checkpoint 执行完整固定评估；
- 失败运行保留最后一个完整 checkpoint 和结构化错误摘要，不提交二进制产物到 Git。

### 14.3 最终验收 G9

- 全部目标、路径模式和固定 seed 的评估单元完整；
- 正式成功率与课程阶段成功率分列；
- 有完整的误差、安全、完成时间、路径覆盖和回归指标；
- 结果可由保存的命令、配置和 checkpoint 三件套独立复现；
- 阶段施工记录均标记实际证据等级，不把静态测试写成 Isaac 或训练通过。
