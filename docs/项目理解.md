# CurriculumRL 项目理解

本文沉淀跨阶段可复用的机理结论。设计真值仍以 `DifferentialIK课程RL_TCP停靠方案与项目迁移说明.md` 为准，阶段是否通过以对应施工记录为准。

## IK 求解与执行器刚度/阻尼的职责差异

### 核心结论

上一个 Lula IK 项目需要机械臂刚度 `6000`、阻尼 `600` 才能获得较高 TCP 跟踪精度，并不表示 Lula 的数学解只有在高增益下才准确。它表示“Lula 生成的关节位置目标”经过 Isaac 隐式位置执行器和物理系统后，需要足够强的关节伺服才能让实际关节紧跟目标。

当前 Differential IK 同样不能绕过执行器。区别在于它每个物理周期读取当前 Jacobian 和关节状态，重新计算小关节增量，并经过单步、速度和位置限幅后写入目标。高频闭环重算能够持续修正未完成的运动，因此对单次 IK 解被精确执行的依赖更低，但最终物理跟踪精度仍受相同的执行器刚度、阻尼、惯量、接触和仿真步长影响。

### 机理拆分

1. **IK 求解层**
   - Lula IK：非线性 IK 根据目标位姿产生关节构型；求解精度描述目标构型在运动学模型中的误差。
   - Differential IK：根据当前 Jacobian 和六维位姿误差产生局部关节增量；阻尼、奇异保护和步长限制决定局部更新的稳定性与速度。
2. **关节目标层**
   - 两者最终都向 articulation 写关节位置目标。
   - Lula 路线更接近“求出一个关节目标，再由伺服器追踪”；当前 Differential IK 是“每个物理周期基于实际状态重新修正目标”。
3. **执行器与物理层**
   - 刚度决定位置误差产生多强的恢复力矩；阻尼抑制速度和高刚度带来的振荡。
   - 刚度过低会产生稳态滞后，阻尼不足会超调或抖动，阻尼过大则响应迟缓。`6000/600` 是执行器跟踪参数，不是 IK 算法参数。
4. **任务精度层**
   - 数学 IK 误差、实际关节跟踪误差、TCP 标定误差和最终停靠成功率是四个不同指标，不能互相替代。

### 当前项目映射

- 执行器基线仍保持机械臂刚度 `6000`、阻尼 `600`，阶段 C 没有调参，因此当前结果不能证明 Differential IK 在更低增益下仍保持同等精度。
- 仿真频率为 `120 Hz`，策略频率为 `4 Hz`，策略增量目标在 `30` 个物理步内保持；Differential IK 每个物理步重新求解并写关节位置目标。
- 常规 DLS 阻尼为 `0.05`；最小奇异值低于 `0.05` 时切换为 `0.20`。
- 单物理步关节增量上限为 `0.02 rad`，等效上限 `2.4 rad/s`，比全局 `3.14 rad/s` 速度限制更严格；位置目标距硬限位保留 `1°` margin。

### 验证状态

- 阶段 C 已验证十二个正负单轴方向、固定位置和固定六维小目标收敛、四环境隔离以及保护触发。
- 固定位置残差约 `4.5 mm`；固定六维综合残差约 `0.00238`，该值混合米和弧度，不能直接解释为毫米。
- 零动作 30 个物理步 TCP 平移漂移约 `1.1 mm`。
- 四个真实目标状态目前只验证向 preposition 接近，尚未证明完整停靠状态机成功。

### 风险与后续验证

- TCP 偏置 `(0.0, -0.12, 0.102) m` 仍为近似标定，会限制真实 TCP 精度。
- 当前 DLS 阻尼在奇异阈值处硬切换，训练分布频繁跨阈值时可能出现控制不连续。
- 若要比较 Lula 与 Differential IK 对执行器增益的依赖，必须固定场景、目标、控制频率和成功判据，对 `6000/600` 及更低增益做独立消融；在完成该实验前，不应声称 Differential IK 可以降低刚度或阻尼。

## 阶段 E 的课程控制与正式评估边界

### 核心结论

阶段 E 已在阶段 D 任务上增加一个全局课程控制器，没有复制环境或另建成功状态机。当前课程等级实际只控制四个目标状态的采样概率和七项辅助奖励的逐项缩放；所有等级共用同一场景、机器人初态、最终成功状态机和安全终止条件。`configs/task.py` 中的 TCP 标定、停车进入/退出距离、速度、姿态、dwell 和安全阈值始终保持不变。P1 的正式评估通过父调度器与单元子进程隔离 SimulationApp，完全绕过自动课程切换，固定使用 L4 课程观测并逐个强制设置四个目标状态。

### 机理拆分

1. **配置层**：`configs/curriculum.py` 定义版本化的等级表、目标采样概率、辅助奖励系数和晋级/回退规则，不复制最终任务阈值。
2. **纯逻辑层**：`logic/curriculum_state.py` 按完整 episode 结果维护滚动窗口；有效 episode 数、成功率和安全失败率共同决定等级转换，并支持无损序列化。
3. **Isaac 运行层**：课程运行时在一批环境 reset 时先汇总旧等级的 episode，再进行一次等级转换，最后按新等级为这些环境采样下一目标。每个环境保存本 episode 的等级，避免异步 reset 把新旧等级统计混在一起。
4. **训练层**：SB3 回调直接导出环境中的结构化课程状态，不解析控制台文本；Checkpoint 同时关联 PPO 模型/优化器、`VecNormalize` 和带配置版本的课程 JSON。课程等级观测已归一化为 `level / 4`，保持阶段 D 的一维观测形状和 L0 数值不变。
5. **评估层**：独立评估入口冻结策略和归一化统计，关闭课程切换及训练随机化，按 4 个目标状态和多个随机种子输出成功率、最终误差、成功时 TCP 速度、各类安全失败率、超时率和完成时间。安全失败与停车事件同一步发生时，正式 episode 结果以安全失败优先，不计为成功。

### 当前项目映射

- L0：只采样 `state_01`；距离进展、历史最佳进展、邻近度和首次进入保持 `1.0`，内区质量和低速停车缩放为 `0.25`，工具轴进展关闭。
- L1：只采样 `state_01`；低速停车缩放为 `0.5`，其余辅助项为 `1.0`，开始完整启用工具轴进展。
- L2：只采样 `state_01`；七项辅助奖励全部为 `1.0`。
- L3：四个目标状态按 `0.25` 均匀采样；七项辅助奖励全部为 `1.0`。
- L4：当前与 L3 的目标分布和奖励缩放相同；尚无通过资产/接触验证的物理随机化，`approved_randomization` 为空。
- 基础奖励权重为距离进展 `20`、历史最佳进展 `10`、邻近度 `0.25`、内区质量 `0.5`、低速停车 `0.5`、首次进入 `2`、工具轴进展 `0.5`、最终成功 `20`、安全失败 `-10`。课程缩放只乘前七项，终局两项不缩放。
- 转换窗口最多保留当前等级最近 `64` 个完整 episode，至少累计 `32` 个才允许判断：成功率 `>=75%` 且安全失败率 `<=5%` 时升一级；成功率 `<30%` 或安全失败率 `>20%` 时降一级。每次转换后冷却 `32` 个完成 episode，单批 reset 最多转换一级。
- reset 顺序为结算旧 episode、尝试一次全局等级转换、按新等级采样下一目标并重置逐环境历史；安全失败与成功同一步发生时按安全失败计，且每个 episode 保存自己的归属等级。
- `scripts/sb3/train.py` 支持从命令行指定初始等级，也支持从配套课程 JSON 恢复实际等级、滚动窗口和冷却状态；恢复时缺少 `VecNormalize` 或课程状态会快速失败。`scripts/evaluate_stage_e.py` 是固定条件正式评估入口，`scripts/sb3/play.py` 仅用于回放。

### 验证状态

- 固定窗口、整批后转换、安全失败覆盖成功、旧等级 episode 不污染新等级窗口、快照恢复和配置版本拒绝已有纯逻辑测试。
- 阶段 E 已完成环境注册、Isaac 动态 smoke、极短训练和带 `VecNormalize`/课程状态的恢复训练。P1 已用一套 smoke checkpoint 在 `1` 个 seed、`4` 个目标、每目标 `4` 个 episode 的矩阵上完成实际 Isaac 复验；每个目标单元在独立 SimulationApp 中结束并落盘，未再发生第二次环境重建阻塞。该证据只验证正式评估运行链，不证明策略学习有效。
- 当前配置版本为 `stage-e-v1-provisional`。`64/32` 窗口、`75%/5%` 晋级门槛、`30%/20%` 回退门槛和 `32` episode 冷却期仍是待阶段 D 足量基线复核的暂定值，不能视为已调优结果。

### 风险与后续验证

- 当前 L3 与 L4 在代码中的训练难度完全相同，L4 只是为未来经批准的随机化预留等级；在随机化落地前不能据此声称已完成最终难度扩展。
- L0/L1/L2 没有改变机器人初态、初始距离或最终约束，只通过辅助奖励缩放形成软课程；设计文档中的“加入姿态/低速/dwell”不能解释为这些任务真值此前被关闭。
- 多环境 reset 的等级归属已有纯逻辑测试，但仍需在 Isaac/SB3 自动 reset 中核对终局张量和完成缓存时序。
- 只恢复 PPO 模型而漏掉 `VecNormalize` 或课程窗口会造成不可复现的继承训练；现有入口会快速失败，但仍需动态恢复测试。
- 训练分布、辅助奖励或课程放宽条件若进入正式评估，会产生虚假成功率；评估配置必须快速失败并审计这些字段。
- L4 随机化必须逐项批准并记录范围，不能用未定义的“完整随机化”替代可复现配置。

### P1 正式评估与课程转换判定的关系

课程转换是训练时的在线控制逻辑：`runtime_state._record_completed_episodes()` 仅在 `curriculum_enabled=True` 时，将本批已完成 episode 的正式成功/安全失败结果提交给 `CurriculumController.submit_batch()`；滚动窗口满足暂定门槛后才升/降级。P1 的 `evaluate_stage_e.py` 及其 worker 则将 `curriculum_enabled=False`，固定 `evaluation_curriculum_level=4` 与单一 `evaluation_target_state_index`，因此不会写入课程窗口、不会调用升降级判定，也不会改变 checkpoint 的课程状态。

两者刻意复用的是较低层契约：同一环境终局缓存、正式成功被安全失败覆盖的优先级、冻结的 PPO/`VecNormalize` 以及课程配置版本检查。前者回答“下一批训练应使用哪个难度等级”，后者回答“冻结策略在最终任务真值下表现如何”；不能用 P1 指标直接触发阶段转换，也不能把课程窗口成功率作为正式评估成功率。

## 分阶段能力课程的设计边界

### 核心结论

“位置到达、姿态对齐、目标泛化、碰撞避障、最终精停靠”的能力顺序合理，但不能把它实现为五个接口和物理语义突然变化的独立任务。Differential IK 是固定的六维任务空间到关节空间执行层，RL 策略学习 TCP 增量的同时，也会从状态—动作—回报分布中学习可达性、冗余构型、奇异区域和路径模式等运动学结构。各阶段应保持相同观测/动作形状、固定最终任务真值，并通过路径模式、动作掩码、采样分布、辅助奖励和分组碰撞逐渐释放能力。完整课程定义统一维护在 `docs/课程设计.md`。

### 机理拆分

1. **同一起终点多路径需要显式分布变量**：路径模式 `z` 是在 episode 开始时采样并写入策略观测的高层路线意图，不是 IK 求解模式、随机种子或一条预先写死的轨迹。相同完整观测下的确定性策略只能产生同一动作；加入 `z` 后策略成为 `π(a|s,z)`，同一物理状态可因路线意图不同产生不同动作序列。仅加入 one-hot 仍可能被策略忽略，因此不同模式还必须绑定可验证的走廊、参考点、轨迹侧别或等价几何约束，并按轨迹距离聚类统计有效模式。无障碍空间只能验证几何轨迹多样性，引入障碍后才能进一步验证不同同伦路径。
2. **位置到姿态不能改变策略接口**：当前动作恒为六维 TCP 增量。位置阶段可保持六维形状但将旋转动作掩码为零或由控制器保持固定参考姿态，姿态阶段再连续放开旋转动作和姿态辅助奖励；直接把三维动作网络替换为六维会破坏 checkpoint 继承。
3. **碰撞使用分阶段配置档**：不能删除机器人、地面、支撑结构或整座工作站的碰撞。课程阶段 1/2 仅选择 C1，阶段 3 切换到 C2，阶段 4/5 使用 C3；课程侧不同时累计启用 C1+C2+C3。空间语义确认使用固定多视角 CameraSensor 的 RGB、深度、实例/语义分割张量，并把分割实例映射回 USD prim；视觉结果负责辅助确认物体身份、空间范围和遮挡，最终碰撞事实仍以 prim 路径和 CollisionAPI 查询为准。
4. **避障需要碰撞前信息**：接触传感器只能在碰撞发生后报告失败。若障碍位置会随机化，而观测仍只有关节状态、TCP/目标误差和目标 one-hot，任务将部分不可观测；至少需要机器人各连杆到障碍的最小距离、射线/深度或等价的障碍状态，并增加净空塑形，最终仍用真实接触判定安全失败。
5. **离散目标不等于泛化**：三个或四个固定目标都可能被策略记忆。当前最终任务有四个目标状态，应逐状态报告最低成功率；若要声称目标泛化，需要在训练目标附近加入连续位置/姿态扰动，或保留未见目标作独立测试，同时保证观测包含相对目标位姿而不是只依赖 one-hot。
6. **精度必须预先定义**：最终位置、姿态、速度、dwell 和安全阈值应在训练前成为固定任务真值。阶段 5 可以提高精度相关辅助奖励、增加近目标样本或采用连续的近端动作缩放，但不能到最后才静默收紧正式成功阈值；若最终要求严于当前 `0.04 m/10°/0.03 m/s/2` 个策略步，必须先修订统一任务契约和全部评估口径。
7. **阶段转换要防遗忘**：升级后仍应混入上一等级的代表性起点和目标，继承 PPO、优化器、`VecNormalize` 和课程状态，并按等级记录 episode 归属。硬切换到全新分布容易造成灾难性遗忘。

### 当前项目映射

- 当前环境动作已经固定为六维，观测包含关节位置/速度、TCP 相对位置和姿态误差、TCP 速度、四维目标 one-hot 与课程等级；适合通过掩码和采样分布实现课程，不宜改变张量形状。
- 当前接触观测只用于 `50 N` 非法接触失败，没有碰撞前净空或障碍几何观测，因此只能支持固定场景的隐式避障，不能直接支持随机障碍泛化。
- 当前四个目标在 `configs/task.py` 中是最终任务真值，并已确定全部参与阶段 3 至阶段 5 训练与逐目标评估。四个离散目标能提高任务内目标覆盖，但仍不能单独证明连续目标泛化；若要声明连续泛化，仍需连续位姿扰动或独立分布外测试。
- 当前策略观测没有路径模式变量，现有课程也没有固定同一起终点的轨迹聚类评估，因此尚不能验证同一起终点的多路径分布。

### 验证状态

以上是由当前动作、观测、接触和任务配置支持的设计评审结论，加上已冻结的视觉语义确认与四目标训练决策，不是新五阶段方案的动态验证。CameraSensor 诊断管线、阶段动作掩码、多起点采样、障碍距离观测、渐进障碍分布和连续目标扰动均尚未实现，也没有对应训练曲线。

### 风险与后续验证

- 每级门禁不能只看总体成功率：至少同时检查分起点/分目标成功率、位置和姿态误差分位数、TCP 到达速度与 dwell、关节限位/奇异保护触发率、碰撞率和超时率。
- 阶段 3/4 应保留阶段 1/2 的回归评估，阶段 5 应在完整场景和全部目标上做固定条件评估，防止后续能力覆盖先前能力。
- TCP 标定误差会形成精度上限；在追求阶段 5 精停靠前必须复核 `(0.0, -0.12, 0.102) m` 偏置，否则奖励调优可能只是在拟合错误 TCP。

## 阶段 D 奖励函数与验证边界

### 核心结论

阶段 D 已实现并接入九项奖励函数，用于向 PPO 提供接近、姿态/速度质量、首次事件、最终成功和安全失败信号；它们不改变最终停靠真值。奖励纯逻辑、跨步历史和有限值已通过单元测试与 Isaac V4 smoke 检查，但现有 8 样本 PPO 仍未学得成功策略，不能据此证明奖励塑形有效。

### 机理拆分

1. **进展与质量**：距离进展、历史最短距离进展、邻近度、内区停靠质量、低速停车和工具轴进展提供稠密信号；历史最优只在新的最短距离出现时奖励，避免往返刷分。
2. **里程碑与终局**：首次进入停车区只奖励一次；最终成功只读取统一停车状态机，因此奖励不能绕过距离、姿态、速度和连续停留条件。
3. **安全**：工作空间越界、非法接触或目标扰动构成安全失败，并以负权重进入奖励；终止条件仍由 Termination Manager 独立判定。
4. **历史隔离**：每个环境保存上一距离、历史最短距离、工具轴对齐和首次进入标记；reset 只清空指定 `env_ids` 的历史，且同一策略步重复查询不会重复提交状态。

### 当前项目映射

- 权重集中于 `configs/rewards.py`：距离/历史最优为 `20/10`，最终成功为 `20`，安全失败为 `-10`；尺度为距离 `0.15 m`、姿态 `0.35 rad`、速度 `0.05 m/s`。
- `logic/rewards.py` 计算九个无 Isaac 依赖的分量，`tasks/tcp_docking/mdp/rewards.py` 仅暴露访问器，`env_cfg.py` 将其组装为 Manager-Based RewardTerm。
- `tests/test_stage_d_logic.py` 覆盖首样本无伪进展、仅新事件获得进展/首次进入奖励，以及部分 reset 隔离。

### 验证状态

- 纯逻辑测试已通过；Isaac V4 smoke 已确认零/随机短回合中观测和奖励有限，记录的总奖励范围约为 `[-0.056906, 0.129638]`。
- 零、随机和 PPO smoke 的完整 episode 对照已能统计总回报及终止原因，但 PPO smoke 仅训练 8 个样本且成功率为 0%，因此不是奖励塑形有效性的证据。

### 风险与后续验证

- 需要用足量短程 PPO，在相同 seed、目标、episode 长度下比较成功率、安全失败率、各奖励分量的 episode 累计值和终止原因；仅总回报上升不能替代成功率改善。
- 辅助奖励权重只能在训练配置中单独消融；不得通过改变最终停车阈值来制造奖励或成功率提升。

## P4 后阶段 1 策略的可用范围

### 核心结论

P4 的 G4 **实际验收通过后**，可以从通过门禁的阶段 1 PPO 运行中选定并保存一个“对阶段 1 有效”的策略，并以其作为后续阶段 2 课程继承训练的初始 checkpoint。严格说，阶段 1 的训练在 P3 的 smoke 和 P4 的多 seed 短程 PPO 实验中已经开始；P4 不是阶段 1 的起点，而是判断该策略是否足以被保存、复现并向后继承的学习门禁。

这个结论不等同于“已得到完整 TCP 停靠的有效策略”。阶段 1 仅覆盖固定初态、一个目标位置、平移动作和 C1 碰撞配置下的位置到达与多路径能力；它不要求姿态对齐，也不覆盖全部目标、完整碰撞避障、随机化或最终精确停靠。最终策略有效性仍需后续 P5--P9 的门禁和固定正式评估证明。

### 判定机制

1. **先满足前置环境门禁**：G1、G2 和 G3 必须已经验收，确保固定条件评估可运行、52 维新观测/课程快照可恢复，以及阶段 1 的旋转动作掩码、路径几何约束、C1 接触和多路径轨迹输出已在 Isaac 闭环中验证。
2. **P4 证明“学到能力”而非只会提高回报**：至少三个固定 seed 的 PPO 短程实验应在相同的 episode 长度和统计口径下稳定优于零动作与随机动作；阶段成功率达标，且安全失败率不恶化。每个路径模式还要有达标的成功率、样本占比和有效轨迹簇，避免策略忽略 `z`。
3. **P4 证明“可复现和可继承”**：同一运行的 PPO checkpoint、冻结的 `VecNormalize` 和课程状态 JSON 必须成套保存，并能独立恢复训练和在固定条件下评估。模型文件单独保存不够，因为遗漏归一化统计或课程快照会改变策略实际接收的观测及继承时的课程状态。
4. **以阶段 1 真值限定策略标签**：当前配置中阶段 1 的位置/速度/dwell 门槛为 `0.08 m`、`0.08 m/s`、连续 `2` 个策略步，旋转动作掩码为零；这只能支持“阶段 1 位置到达与多路径策略”的标签。它不能替代最终 `0.04 m`、`0.03 m/s`、姿态 `10°`、连续 `2` 个策略步及安全约束的正式停车判定。

### 当前项目映射与证据边界

- P0 已验收；P1 已有单 seed、四目标的最小 Isaac 评估运行链证据，但 G1 仍缺故障注入和冷启动重复性动态证据。P2 已完成 52 维接口、阶段成功隔离和快照版本拒绝的最小验证。
- 当前工作区的 P2 纯逻辑回归（课程 schema、P2 状态逻辑、阶段 E 状态逻辑和评估逻辑）为 `16 passed`。这是静态/纯逻辑证据，不是 PPO 学习或策略性能证据。
- P3 已完成动作掩码执行、路径参考点约束、7 个单刚体 C1 过滤传感器及阶段 1 Isaac smoke；但尚未在受控真实碰撞中证明 C1 力超过阈值后确实进入终止。因此 G3 仍未关闭。P4 的三 seed 学习对照、路径簇评估、三件套动态恢复和 `4/16/32/64` 环境基准也尚无证据，不能保存并称任何 checkpoint 为“阶段 1 有效策略”。

### 保存与验收要求

被选为阶段 1 起点的运行应至少保留：PPO 模型（含优化器状态）、对应 `VecNormalize` 文件、课程状态 JSON、环境/agent 配置快照、命令、seed、run tag、训练预算和固定评估报告。只有这些产物指向同一配置版本、观测 schema 和实验运行，且 G4 指标通过，才将其标记为“阶段 1 有效、可继承”；不应将其标记为“最终停靠有效”。

## C1 玻璃实体接触注入的验收意义

### 核心结论

受控撞击 C1 玻璃不是用来训练“撞玻璃”或评估避障策略质量；它是一次故障注入，用来验证**碰撞后安全失败链路**。只有当非 `Base_Link` 的机器人刚体与 C1 玻璃发生真实物理接触，过滤后的接触力超过固定阈值 `50 N`，并在同一环境中令 `illegal_contact` 终止项为真，才能证明 C1 的资产 prim、ContactSensor、force matrix 汇总、阈值判定和 Termination Manager 是闭环一致的。

### 机理拆分

1. **过滤范围**：C1 只对应 `.../WorkStation/Glass/M_Glass`。测试应确认来自该 prim 的力会进入 C1 force matrix，而未启用的 C2 工作站主体接触不会被错误算作 C1 失败。
2. **阈值与刚体范围**：`ILLEGAL_CONTACT_FORCE_N=50.0 N` 是任务真值；`Base_Link` 被排除，`Link_01` 至 `Link_05` 与 `Flange` 参与判定。该测试验证的是逐环境、逐刚体、按过滤体聚合后的力范数阈值，而不是 TCP 位置误差。
3. **结果优先级**：一旦非法接触为真，它属于 safety failure；即使同一步满足阶段或正式停车条件，安全失败也应覆盖成功。终止项与负向安全奖励分别消费同一个安全状态，不应由脚本直接伪造 done。

### 当前项目映射与证据边界

- P3 已在真实 Isaac 场景中验证 7 个单刚体 C1 ContactSensor 均生成有限的 `(env, 1, 1, 3)` `force_matrix_w`，并在运行时拼成 `(env, 7, 1, 3)` 后送入 `illegal_filtered_contact()`。
  - P3 的受控故障注入已在真实 Isaac 物理步中验证：将固定基座根位姿平移 `(0.70, 0.00, 0.30) m` 后，`Link_04` 对 C1 Glass 的过滤接触力为 `16,516.552734375 N`，同一步通过正式 `TerminationManager` 得到 `illegal_contact=True`、`terminated=True`。这确认了碰撞后的 C1 失败闭环；并不证明策略具有碰撞前避障能力。

### 风险与后续验证

- 受控动作应仅让一个非基座连杆或 Flange 以受限速度接触玻璃，并记录碰撞前后 C1 力、body 名称、环境编号、`illegal_contact` 与终止原因；验证结束后恢复正常初态和控制参数。
- 该故障注入不替代 P4/P7 的碰撞前净空、路径质量或学习效果评估。接触传感器只在已经碰撞后报告，因此不能证明策略具备碰撞前避障能力。

## 可视化训练中的 Differential IK 与帧率

### 核心结论

P4 的训练和评估链仍使用 Differential IK，不会把 PPO 的六维动作直接写成关节目标。当前可视化窗口出现“每次跳一段”的直接原因是环境把渲染间隔设为与策略 decimation 相同的 `30` 个物理步：物理与 Differential IK 仍以 `120 Hz` 运行，但视窗只约以 `4 FPS` 更新。控制台的 `1 it/s` 是 SB3 外层 PPO 迭代吞吐，不是 Differential IK、物理仿真或策略动作的频率。

### 机理拆分

1. PPO 每个策略步输出一个六维根坐标系 `B` 下的 TCP 增量；阶段 1 的后三个旋转分量先由课程动作掩码置零。
2. 动作项将该增量缩放为 TCP 目标位姿；每个物理步读取当前 Jacobian 与实际关节状态，以阻尼最小二乘求解关节增量，再进行单步、速度和位置限幅后写入关节位置目标。
3. 一个策略增量保持 `30` 个物理步，因此策略频率为 `4 Hz`，但 Differential IK 在这 `30` 步中持续重算和修正；它不是每秒只求解一次。
4. 渲染是独立于物理与控制的消费层。若渲染也每 `30` 个物理步才刷新，窗口只能看到策略步边界的离散画面，即使中间的 29 个物理步仍在计算和执行。

### 当前项目映射

- `TcpDockingEnvCfg` 以 `SIMULATION_DT_S=1/120 s`、`POLICY_DECIMATION=30` 配置环境，同时将 `sim.render_interval` 设为 `30`；策略频率固定为 `4 Hz`。
- `DifferentialIKActionTerm` 是环境唯一的 `tcp_delta` 动作项。其 `process_actions()` 读取课程动作掩码，`apply_actions()` 调用 Differential IK，并在诊断开启时保存最小奇异值、阻尼、关节增量和各种限幅标志。
- P4 评估 worker 为该动作项打开诊断，并在每个策略步统计 `singular`、`delta_limited`、`velocity_limited` 和 `position_limited`。最小 Isaac 基线实际生成了这些统计，因此确认 P4 运行链实际经过该控制器；它不等同于 PPO 已学会策略。

### 验证状态

- 当前结论由训练/环境配置、动作项调用链和 P4 最小 Isaac 基线的控制器诊断可用性共同支持。
- 未对“每物理步实际 TCP 位移是否平滑”生成逐物理步视频或时间序列；当前 4 FPS 可视化不足以凭肉眼验证该物理层性质。

### 风险与后续验证

- 为了观察连续物理运动，应为可视化运行单独提高渲染频率，而不能改变 `sim.dt`、decimation、动作尺度或任务阈值；训练吞吐会随之下降。
- 视频录制、单环境 GUI 与 PPO 更新都会显著降低 `it/s`，尤其在 CPU 或实时渲染下。性能基准应在关闭 GUI/视频的 headless 条件下单独测量。
- 迁移说明文档当前在工作区中处于删除状态；上述结论以现行代码与施工记录为准，恢复该文档后仍应核对其频率契约。

## 回放录像卡顿与调试超时崩溃

### 核心结论

回放期间持续输出“PPO action 已生成”和“env.step() 已完成”，证明 checkpoint 推理、Differential IK 动作链和物理步都在持续返回；此前不是策略、IK 或环境死锁。首次卡顿时的 `OgnSdPostRenderVarToHost` 警告对应录像渲染帧从 GPU 纹理回读到主机内存，属于高开销路径，会明显降低吞吐，但不等同于控制失败。

此前约在第 `21 s` 出现的 Kit crash 与 `--debug-traceback-timeout-s 20` 精确对应。旧实现调用 `faulthandler.dump_traceback_later()` 的原生定时回溯；在 Windows Isaac Kit 进程中该调试方式会触发崩溃。现改为普通 Python 守护线程在检查点静默超过阈值时通过 `sys._current_frames()` 输出栈，因此保留诊断能力而不改变回放控制链。

### 当前项目映射

- `scripts/sb3/play.py` 在 PPO 推理前后及 `env.step()` 前后输出可选检查点；`--debug-progress-interval 1` 可逐策略步确认闭环仍在推进。
- `--debug-traceback-timeout-s` 仅启动 `replay-python-watchdog`；它不修改 PPO 动作、`sim.dt`、decimation、渲染间隔、Differential IK 参数或课程状态。
- `--video` 启用 `RecordVideo` 与 `rgb_array` 渲染；`--render-interval 2` 令内部渲染以 `120 / 2 = 60 Hz` 刷新，但 GPU 到主机的录像帧读回仍可能成为性能瓶颈。

### 验证状态

- 原生超时回溯替换后，用户现场回放能够稳定连续输出策略步检查点；这是“PPO 推理至 `env.step()` 的运行链未卡死”的动态证据。
- 脚本已完成语法、命令行参数及 P4/评估逻辑单测验证；未在当前工作站重新执行用户的完整五回合视频录制。

### 风险与后续验证

- 若只需判断策略和环境是否前进，应先不带 `--video` 运行少量 `--steps`；若仅在带视频时变慢或停止，故障边界就是渲染/编码，而不是 Differential IK。
- 录制吞吐和训练吞吐必须分开统计；`OgnSdPostRenderVarToHost` 警告可作为优化信号，但不能单独作为仿真或策略异常的证据。

## P4 训练曲线、奖励建模与超时

### 核心结论

P4 的 `rollout/ep_rew_mean` 上升不能单独证明策略学会阶段 1。正式 seed-7 训练中，平均回报从 `1.1487` 上升到 `8.1006`，同时平均 episode 长度从 `136.91` 上升到 `156.56/160`；20 个记录点的回报与长度 Pearson 相关系数为 `0.5996`。固定评估又出现 `100%` 超时和 `0%` 课程成功，因此曲线反映的是“获得了更多塑形奖励”，不是“更快完成任务”。

当前奖励建模具有促成超时局部最优的结构性风险：`proximity` 在每个策略步持续给正奖励，没有逐步时间成本；L0 课程成功既不是终止项，也没有独立事件奖励，终止仍只认正式停车、安全失败或 40 秒超时。课程成功状态还会在后续不再满足门槛时撤销，并仅在 episode 结束时提交。这会使“长时间靠近但不完成”与“尽快达到 L0 门槛”的价值差距不足，并可能漏掉曾短暂达到阶段门槛的轨迹。

### 机理拆分

1. Isaac Lab `RewardManager` 将每项权重再乘环境步长 `dt=0.25 s`。因此配置中的 `FINAL_SUCCESS_WEIGHT=20` 对一次正式成功实际贡献 `5`，`PATH_REFERENCE_REACHED_WEIGHT=1` 实际贡献 `0.25`。P4 JSON 的 `weighted_reward_components` 为乘 `dt` 前的诊断累计值，其总和再乘 `0.25` 才与 SB3 episode return 一致。
2. `distance_progress` 是相邻距离的有符号变化，`best_progress` 和路径参考点进展只奖励新的历史最优；这些项推动接近，但不保证跨过最终门槛。`proximity=exp(-distance/0.15)` 则可在整个 160 步中持续累积。
3. L0 课程成功要求位置误差不超过 `0.08 m`、TCP 速度不超过 `0.08 m/s`、连续 `2` 个策略步并且曾到达 `0.04 m` 容差的路径参考点；正式停车仍要求更严格的固定任务条件。当前训练没有专门奖励或终止 L0 成功事件。
4. PPO 配置使用未 squash 的高斯动作。最终策略的原始动作绝对值最大达到约 `6.12`，而 Differential IK 动作适配器会把每轴平移增量裁剪到 `0.02 m`；因此大量不同原始动作映射到相同饱和值，降低动作梯度与实际运动之间的可辨识度。

### 当前动态证据

- 新的 P4 行为诊断对 direct 路径单回合记录到：初始距离 `0.8054 m`，最小距离 `0.1247 m` 出现在第 76 步，终局距离 `0.1955 m`；最小路径参考点距离 `0.0740 m`，未达到 `0.04 m` 容差。
- 该回合 TCP 路径长度约 `1.1176 m`、净位移约 `0.6190 m`，说明策略在运动而非原地停滞；但处理后平移动作与目标方向的平均余弦为 `-0.2067`，实际 TCP 运动与目标方向的平均余弦为 `-0.0976`，分别有 `53.1%` 和 `58.5%` 的有效样本未朝向目标。
- 控制器诊断中 `delta_limited=50%`、`singular=10.625%`，速度限幅和位置限幅未触发。当前最直接的行为失败是动作方向不稳定并频繁进入增量限幅；奖励设计的超时偏置会放大该问题，但仅凭一次训练不能把全部失败归因于奖励。
- P4 评估 schema 已升级到 `p4-stage1-evaluation-v2`，逐 episode 保存动作统计、目标/参考点距离、阶段门槛连续步数、运动方向一致性、控制器保护比例及按步长抽样的行为轨迹；终局指标继续从 auto-reset 前缓存读取。

### 风险与后续验证

- 下一次训练应把课程成功率、超时率、最小距离、路径参考点到达率和奖励分量写入 TensorBoard；仅看总回报和 PPO loss 无法选择 checkpoint。
- 奖励修订应做受控消融：比较加入小幅时间成本、将 L0 课程成功设为训练终止/一次性奖励、以及限制策略输出分布后的成功率和安全失败率。不得通过放宽正式停车阈值制造成功。
- 在修改奖励前应先固定当前 checkpoint 的行为报告作为基线；修改后使用相同 seed、episode 长度、路径模式和评估入口复跑，才能判断超时率下降来自奖励因果而非随机波动。

## 肘型偏好、IK 奖励与 PPO 辅助 Loss 的边界

### 核心结论

当前 Differential IK 不是在每步枚举全局解析 IK 的肘上/肘下候选后自动选解，而是以当前关节状态为线性化点，用 `Jᵀ(JJᵀ+λ²I)⁻¹e` 计算局部关节增量。因此肘型首先由 reset 初态、目标采样可达域和连续运动路径决定；奖励或 PPO Loss 只能让策略间接避开不希望的姿态，不能可靠替代控制层的构型分支约束。

如果“肘上”是工业运行必须满足的硬约束，应先用经资产关节方向和几何验证的肘型判据，选择肘上 reset 关节姿态，并保证目标与参考路径在该连续构型分支内可达。需要全局重定位时，应在 reset 或稀疏路点层用肘上种子/候选筛选确定连续参考，再由 Differential IK 局部跟踪；不应在每个物理步的奖励中重复运行全局 IK。

### 机理拆分

1. **奖励方案可作辅助，但不宜把求解器本身当奖励**：更合适的是直接根据实际关节角或肩—肘—腕几何计算连续的肘上裕量，并结合关节限位裕量、最小奇异值、TCP 跟踪残差和连续限幅次数做小权重塑形。每步另跑一次全局 IK 再比较结果会增加并行环境开销，并在多解切换、不可达和求解容差附近产生不连续标签。
2. **单步 IK 保护不等于执行失败**：`singular` 只表示最小奇异值低于阈值并触发更大阻尼；`delta_limited`、`velocity_limited`、`position_limited` 表示安全投影生效。这些通常是可恢复事件，适合记录、观测或轻度惩罚，不应首次出现就终止。
3. **失败必须分级**：NaN/Inf、Jacobian 契约错误或线性求解异常属于实现/运行故障，开发和验收阶段应快速失败，不能伪装成正常 MDP 样本。训练时若能可靠隔离到单个环境，则可停止写入危险目标、标记独立 `controller_fault` 并终止该环境。普通残差、近奇异或偶发投影先继续控制；只有连续若干策略步残差不降、保护持续饱和且状态已不可恢复，才考虑带负奖励的错误终止。安全边界被破坏则仍由正式 workspace、接触和目标扰动终止负责。
4. **PPO Loss 方案需要改训练架构**：当前 SB3 使用标准 `PPO(MlpPolicy, ...)`，Differential IK 位于环境动作适配链，跨过 VecEnv/仿真后不在策略的自动微分图内。不能仅把环境里的 IK 误差张量加进 Loss 就获得有效梯度；必须自定义 PPO/rollout buffer，存储肘型或参考关节标签，并增加可微辅助头或教师模仿目标。
5. **动作与监督语义必须一致**：当前策略输出的是根坐标系 `B` 下的六维 TCP 增量，而全局 IK 输出的是六个关节角；二者虽然都是六维，物理含义不同，不能直接计算监督 Loss。若采用教师模仿，应明确让策略预测关节参考、构型标签或新增的姿态偏好量，并重新定义动作接口及安全投影。
6. **六自由度满位姿任务通常无姿态零空间**：六关节机械臂在 `6×6` Jacobian 满秩且同时约束 TCP 位置与姿态时，零空间维数为零。常见的 `N(q_ref-q)` 姿态偏置不能在保持完整末端位姿的同时自由选择肘型；只有放松部分任务、处于冗余阶段或改成带位姿松弛的约束优化时，姿态正则才有真实自由度。
7. **Joint2 包络不等于肘型判据**：限制 Joint2 相对参考角的偏离可以约束肩部俯仰和缩小搜索空间，但同一 Joint2 角度仍可能随 Joint1、Joint3、腕部姿态和目标位置形成不同的肩—肘—腕几何。若任务真值是“始终肘上”，应将 Joint2 包络作为关节约束，并用独立的肘部几何裕量监控构型分支。

### 当前项目映射

- 机器人每次 reset 使用固定初态：`Joint1=0°`、`Joint2=-30°`、`Joint3=70°`、`Joint4=45°`、`Joint5=90°`、`Flange=0°`。该姿态究竟对应资产中的肘上还是肘下，必须按实际关节轴和几何标定，不能只按 UR5 通用符号约定判断。
- 若将 Joint2 的 `[-60°, 60°]` 定义为相对 reset 参考值 `-30°` 的偏离，则任务包络对应实际 Joint2 角度 `[-90°, 30°]`；若该区间指绝对角度，则实际包络为 `[-60°, 60°]`。配置与诊断必须明确采用哪一种语义，不能混用。
- 控制器在每个物理步从当前关节状态求局部 DLS 增量，随后执行 `0.02 rad` 单步上限、`3.14 rad/s` 速度上限和 `1°` 位置限位裕量投影；现实现没有全局 IK 候选枚举、肘型选择器或姿态参考正则。
- 策略观测已包含六关节位置和速度，因此奖励塑形在信息上可学习；但训练动作只控制 TCP 增量，不能保证策略从一个不合适的初始构型跨越到另一离散 IK 分支。
- 当前奖励只消费距离、姿态、速度、路径、成功和安全状态；当前终止只包含正式停车成功、TCP 越工作空间、非法接触、目标扰动与超时。控制器诊断默认关闭，仅评估和 smoke 入口显式打开，尚未形成训练时的每环境失败状态。

### 验证状态与后续实验

- 上述结论由现行控制器、reset、观测、奖励、终止和 SB3 训练入口的静态代码支持。用户提供的 Isaac 视窗截图按当前项目命名可作为一个肘上姿态的视觉基准，但单帧截图只证明观察时刻的外观，不能证明它就是 reset 初态、整条轨迹始终保持该分支，或某种新奖励/Loss 能提高正式成功率。
- 首先应固定一组目标和 seed，记录肩、肘、腕世界坐标、六关节角、肘型连续裕量、最小奇异值、TCP 残差及保护标志，确认动作混乱是初态构型、接近奇异、限幅饱和还是策略方向问题。
- 推荐按因果强度做消融：肘上初态/连续可达目标基线；再加入小权重肘型与可操作度奖励；最后才比较自定义辅助 Loss。各组使用相同训练预算并比较正式成功率、安全失败率、超时率、肘型违规率和控制器保护率。
- 二值肘型奖励、单次奇异即终止和每步 CPU 全局 IK 都可能造成稀疏/不连续学习信号、过早截断或严重吞吐下降，应避免作为首选实现。

## 六轴角度作为导出结果或策略动作的边界

### 核心结论

当前项目已经在 Differential IK 动作链末端生成六个关节位置目标 `joint_target`，因此仅把六轴角度用于显示、记录或下游接口属于小范围数据出口改动。若让 PPO 直接输出六轴角度，则虽然动作张量仍为六维，却改变了每一维的物理语义，属于新的策略谱系，不能沿用现有 checkpoint、TCP 动作掩码和评估解释。

### 机理拆分

1. 当前策略在 `4 Hz` 输出根坐标系 `B` 下的三维 TCP 平移增量和三维旋转向量；Differential IK 在 `120 Hz` 物理步上求六关节增量，经单步、速度和位置限幅后写入关节位置目标。
2. 仅导出时应区分“目标关节角”与“仿真实际关节角”：前者来自控制器 `joint_target`，后者来自 articulation `joint_pos`；两者之差反映执行器和物理跟踪误差。
3. 直接关节动作必须重新定义绝对角或增量角、弧度或角度、归一化映射、关节顺序、每策略步变化上限和动作保持方式。绝对角命令若缺少速率限制，可能在相邻策略步产生不连续跳变。
4. 当前课程的 `tcp_action_mask` 表示平移/旋转轴是否启用，不能机械地解释为六个关节掩码；基于 TCP 方向的动作诊断、Differential IK 奇异与限幅统计也需要替换或保留为独立的安全监控。

### 当前项目映射

- 六关节顺序由资产契约解析，动作适配器最终调用 `set_joint_position_target(..., joint_ids=...)`。
- 策略观测已经包含六关节位置和速度，任务奖励和正式成功仍以 TCP 距离、姿态、速度、停留和安全条件为主。
- 动作维数保持为 `6` 不代表旧模型兼容；SB3 可能只看到相同张量形状而无法发现语义错配，因此需要新的任务/动作 schema 标识并从头训练或使用明确的教师迁移。

### 验证状态与风险

上述结论来自当前配置、动作适配器、观测 schema、评估脚本和纯逻辑测试的静态证据；本节未改产品代码，也未运行新的 Isaac 闭环实验。直接关节动作的主要风险是策略需要同时学习运动学与任务规划，训练样本需求、碰撞风险、关节限位饱和和构型跳变通常都会高于保留 Differential IK 的方案。
