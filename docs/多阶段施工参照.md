## 1. 用途与执行规则

本文把迁移说明转换为可逐阶段执行的施工、验证和验收门禁。它不表示当前工作区已经具备资产、场景、控制器或训练能力。

执行时遵守以下规则：

1. 严格按“配置 → 纯逻辑 → Isaac 适配/执行 → 训练与数据输出”的方向建立依赖。
2. 每个阶段只能在上一阶段验收通过后开始；失败时回到本阶段修复，不通过修改后续阶段掩盖问题。
3. 每次施工只完成一个可独立验证的批次，保留目标文件 diff、验证命令和结果。
4. 资产路径、TCP 标定、目标状态、最终成功阈值和安全阈值均保持单一事实来源。
5. Lula 只作为行为对照，不进入新 Differential IK 方案的运行依赖。
6. 未实际启动 Isaac 仿真、训练或正式评估时，不得把对应项目记录为“通过”。

若本文与迁移说明冲突，以迁移说明中的任务真值为准；若实现结果与资产实际结构冲突，停止施工并先更新资产契约和验收记录。

## 2. 当前工作区落地边界

迁移说明中的推荐目录是职责模型。在当前 Isaac Lab 外部扩展中，产品代码应落到 Python 包根目录，而不是仓库根目录：

|---|---|---|
| `configs/` | `source/CurriculumRL/CurriculumRL/configs/` | 只保存资产契约、参数和不可变任务真值 |
| `logic/` | `source/CurriculumRL/CurriculumRL/logic/` | 不导入 Isaac、SB3，不执行文件写入 |
| `runtime/` | `source/CurriculumRL/CurriculumRL/runtime/` | 负责 Isaac 场景访问、接触读取和训练适配 |
| `tasks/tcp_docking/` | `source/CurriculumRL/CurriculumRL/tasks/tcp_docking/` | 组装动作、观测、事件、奖励、终止和课程 |

当前 `tasks/manager_based/curriculumrl/` 和 `tasks/direct/` 属于模板基线。新任务使用独立的 `tasks/tcp_docking/`，不得把新任务逻辑分散写入模板任务。模板清理应在新任务注册和最小运行入口稳定后作为独立批次执行。

## 3. 固定任务真值

以下契约贯穿全部阶段。任何调整都必须单独评审，不得作为控制器调参或课程调参的附带修改。

| 类别 | 固定值 |
|---|---|
| 受控场景实体 | `AUBObot`；`AUBObot_2` 只加载、不由策略控制 |
| articulation prim | `AUBO_E5` |
| 末端刚体 | `Flange` |
| 机械臂关节 | `Joint1`、`Joint2`、`Joint3`、`Joint4`、`Joint5`、`Flange` |
| 夹爪关节 | `UpperFinger`、`DownFinger`，不得进入机械臂 IK 向量 |
| 目标场景 key | `ws_interactive_reagent_01_sample_bottle` |
| 最终进入/退出距离 | `0.04 m` / `0.055 m` |
| 最终速度阈值 | `0.03 m/s` |
| 最终姿态阈值 | `10°` |
| 最终连续停留 | `2` 个策略控制步 |
| 仿真/策略频率 | `120 Hz`；decimation `30`；策略 `4 Hz` |
| Episode | `40 s`，最多 `160` 个策略步 |
| 四元数顺序 | `wxyz` |
| 策略动作坐标系 | 机器人根坐标系 `B` 下的六维 TCP 增量 |

必须保留 4 个离散目标状态、TCP 法兰局部偏置、姿态旋转契约、工作空间、非法接触力、目标位移和目标速度阈值。具体数值只在 `configs/task.py` 定义，其他模块通过导入或显式参数使用。

## 7. 阶段 A：工作区与资产

### 7.1 批次 A1：目录与配置骨架

建立以下最小包结构，不提前填入训练逻辑：

```text
source/CurriculumRL/CurriculumRL/
├─ configs/
│  ├─ assets.py
│  ├─ scene.py
│  ├─ task.py
│  ├─ differential_ik.py
│  ├─ curriculum.py
│  └─ training.py
├─ logic/
├─ runtime/
└─ tasks/tcp_docking/
```

`configs/assets.py` 是 `ASSET_ROOT`、USD 相对路径和 prim 契约的唯一来源。启动检查应报告缺失文件及其解析后路径，但不得在配置导入时启动仿真或写文件。

### 7.2 批次 A2：资产和 articulation 检查

- 检查带夹爪 AUBO、样品瓶及停靠所需工作站拆分 USD。
- 递归确认顶层 USD 引用的材质、纹理、子 USD 和碰撞定义可解析。
- 解析并记录六个机械臂关节、两个夹爪关节和 `Flange` body id。
- 验证机械臂关节唯一匹配且顺序显式；不得依赖字符串列表的假定顺序。
- 验证 `Flange` 可读取位姿、线速度、角速度和 Jacobian。
- 验证机器人 spawn 启用接触传感器。

### 7.3 批次 A3：单环境静态场景

- 按迁移说明中的工作站基准位姿和机器人局部位姿组装单环境场景。
- 加载 `AUBObot`、`AUBObot_2`、目标和最小工作站子集；相机、RTX 和 RGB-D 暂不进入依赖。
- 机器人初态和执行器参数先原样迁移，不在本阶段调增益。
- 提供 `scripts/inspect_assets.py` 或等价只读检查入口，以及 `scripts/smoke_env.py` 的静态加载模式。

### 7.4 验收门禁

- V0 通过。
- 单环境静态场景可启动并关闭，无缺失资产、错误 prim 或未解析关节。
- 场景中两台机器人和目标的位置与坐标约定一致。
- 夹爪关节未混入六轴机械臂索引。
- 资产、prim 和关节/body 解析结果已写入验收记录。

若资产依赖缺失、`Flange` 无 Jacobian、关节匹配不唯一或接触传感器无法激活，阶段 A 阻塞，不进入阶段 B。

## 8. 阶段 B：场景与任务真值

### 8.1 批次 B1：纯逻辑迁移

在 `logic/` 中实现并测试：

- `tcp_kinematics.py`：法兰位姿到 TCP 位姿、带偏置切向项的 TCP 线速度、世界系到根坐标系转换。
- `orientation.py`：期望法兰姿态、工具轴夹角和对齐分数。
- `parking_state.py`：进入/退出迟滞、低速、姿态和 dwell 状态机。
- `curriculum_state.py`：只定义课程统计和状态转换，不在本阶段接入训练。

纯逻辑函数只接收显式张量和参数，不读取场景、全局环境或文件。测试至少覆盖：单环境/多环境、四元数顺序、环境原点偏移、迟滞边界、dwell 清零和同一控制步只提交一次。

### 8.2 批次 B2：目标与 reset 数据流

- 在 `configs/task.py` 定义 4 个目标状态、TCP 标定、最终阈值和安全阈值。
- Reset 对指定 `env_ids` 原子执行：选择状态、局部转世界、写位姿并清速度、回读基准、缓存 preposition/期望姿态、清历史状态。
- 同时验证全环境 reset 和部分环境 reset，未选环境的缓存与仿真状态不得变化。
- 目标状态、目标基准和历史奖励缓存均使用逐环境张量。

### 8.3 批次 B3：接触、失败条件和最终状态机

- ContactSensor 匹配 `{ENV_REGEX_NS}/AUBObot/AUBO_E5/.*`。
- 明确解析 contact tensor 的环境维和 body 维，排除 `Base_Link`，其余机器人刚体参与非法碰撞判定。
- 实现工作空间、非法接触、目标位移、目标速度和超时失败条件。
- 奖励实现可暂缓，但最终成功只能来自统一停车状态机。

### 8.4 验收门禁

- V1 全部通过；新旧基线的代表性输入产生一致的 TCP 状态、姿态误差和成功判定。
- V2 动态 smoke 通过；目标可写入、回读和部分 reset。
- 进入/退出迟滞、速度、姿态和连续停留条件均在最终状态机中生效。
- reset 后进展、里程碑、停车区、dwell 和控制步缓存全部清空。
- 非法接触能正确排除 `Base_Link`，且多环境维度无串扰。

若 TCP 偏置尚未实测，可保留已确认的第一版近似值继续控制器施工，但必须在验收记录中保留风险，且正式评估前必须复核。

## 9. 阶段 C：Differential IK

### 9.1 动作与求解契约

策略动作固定为根坐标系 `B` 下的六维 TCP 增量：三维平移和三维旋转增量。`configs/differential_ik.py` 集中定义动作尺度、旋转表示、阻尼、单步变化、关节位置/速度限幅和奇异保护阈值。

`tasks/tcp_docking/actions.py` 负责：

1. 裁剪并缩放策略六维原始动作；
2. 生成目标 TCP 增量位姿；
3. 读取已解析顺序的机械臂关节状态和 `Flange` Jacobian；
4. 处理固定基座/浮动基座 Jacobian body 索引差异；
5. 使用阻尼最小二乘计算六关节增量；
6. 执行关节限位、速度限位、单步变化和有限值检查；
7. 写入关节位置目标。

不得导入 Lula URDF、robot description、Lula 求解器或旧 `AuboTaskSpaceIKAction`。

### 9.2 分步施工与验证

1. 零动作保持：固定初态下关节目标有限、TCP 不发生非预期漂移。
2. 单轴微动：分别验证 `+/-x`、`+/-y`、`+/-z` 和三个旋转轴的方向、尺度和坐标系。
3. 固定位置目标：只启用平移，误差应稳定下降。
4. 固定六维目标：同时启用位置和姿态，检查阻尼与限幅。
5. 多目标和多环境：覆盖 4 个目标状态，确认环境间无索引串扰。
6. 奇异与边界：在接近关节限位或 Jacobian 病态时验证保护行为。

诊断输出必须可关闭，并至少能记录：原始动作、限幅后 TCP 命令、Jacobian 形状、阻尼/奇异标志、关节增量、限位投影、最终关节目标、期望与实际 TCP 变化。

### 9.3 验收门禁

- 所有动作链张量有限，无 NaN/Inf，形状与环境数一致。
- 六个机械臂关节顺序与 Jacobian 列顺序一致，夹爪列未进入求解。
- 固定位置和六维目标测试中，位置与姿态误差总体稳定下降。
- 无关节越界、速度越界、持续奇异抖动或动作方向颠倒。
- `sim.dt`、decimation 和动作保持方式与 `120 Hz / 30 / 4 Hz` 契约一致。
- V3 验收记录包含至少一个成功轨迹和一个保护机制触发样例。

未通过阶段 C 前禁止启动 PPO；执行器增益调优与 IK 公式修改应拆为不同批次。

## 10. 阶段 D：基础 RL

### 10.1 环境组装

- 在 `tasks/tcp_docking/env_cfg.py` 组装 Manager-Based 环境。
- 观测至少包含关节位置/速度、TCP 到 preposition 的位置误差、姿态误差、TCP 线/角速度、目标状态和课程等级。
- 奖励组装距离进展、历史最佳进展、邻近度、内区停靠质量、低速停车、首次进入、工具轴进展、最终成功和安全惩罚。
- 最终成功奖励只绑定统一停车状态机；历史最佳进展只奖励新最短距离。
- 终止保持 `terminated` 与超时 `truncated` 语义分离。
- 训练默认不加载相机，数据和日志不得反向影响任务逻辑。

### 10.2 最小训练范围

- 固定最简单目标状态和受控初始分布。
- 先运行零动作、随机动作和短回合并行 reset，再启动短程 PPO。
- Checkpoint 名称关联任务、课程等级、随机种子和运行标签，并保存配置快照。
- 独立进程从保存的 Checkpoint 回放，不依赖训练进程内存状态。

### 10.3 验收门禁

- 多环境 reset 无串扰，观测、奖励、终止和动作均为有限值。
- 奖励各项和终止原因可以统计，数量级可解释，无单项意外支配总奖励。
- 最简单固定目标的成功趋势优于零动作和随机动作基线。
- Checkpoint 可在相同配置下独立加载和回放。
- 日志包含任务、课程等级、种子、运行标签和配置快照引用。
- V4 通过后才允许扩大目标分布或引入随机化。

短程训练没有达到最终成功率目标时，不代表环境门禁失败；但若无学习趋势、统计不可解释或回放不一致，则阶段 D 不通过。

## 11. 阶段 E：课程 RL 与正式评估

### 11.1 课程等级参照

课程的精确阈值应在阶段 D 基线数据形成后写入 `configs/curriculum.py`。建议只按以下能力顺序展开：

| 等级 | 新增训练难度 | 保持不变 |
|---|---|---|
| L0 | 固定目标、位置接近 | 最终状态机和安全真值 |
| L1 | 加入姿态对齐 | 正式评估阈值 |
| L2 | 加入低速进入与连续停留 | TCP 标定和坐标契约 |
| L3 | 扩展至全部 4 个目标状态 | 最终成功奖励来源 |
| L4 | 启用完整碰撞约束和经批准的随机化 | 最终评估分布与指标定义 |

课程可改变目标采样分布、初始距离、辅助奖励权重和约束启用顺序，不得改变最终进入/退出距离、速度、姿态、dwell 和安全真值。

### 11.2 晋级、回退和继承

- 使用滚动成功率、有效 episode 数和安全失败率共同决定晋级。
- 晋级统计进入统一回调，不解析控制台文本。
- 晋级与回退必须记录原因、统计窗口、旧/新等级和配置版本。
- 下一等级可继承上一等级 Checkpoint，但优化器状态、归一化统计和配置兼容性必须显式检查。
- 训练成功和课程晋级不得替代固定条件的正式评估。

### 11.3 正式评估

冻结训练后，在固定最终阈值下按 4 个目标状态分别执行多随机种子评估，至少输出：

- 停靠成功率；
- 最终位置误差和姿态误差；
- 成功时 TCP 速度；
- 非法碰撞率、目标扰动失败率和超时率；
- 平均完成时间；
- 任务、Checkpoint、随机种子和完整配置快照。

若保留 Lula 对照，只能使用相同场景、目标分布、最终状态机和终止定义进行比较。

### 11.4 最终验收门禁

- 全部 4 个目标状态均有独立指标，不用总体均值掩盖失败状态。
- 正式评估没有课程放宽阈值、辅助成功或训练分布泄漏。
- 课程状态可从 Checkpoint 和配置快照恢复，恢复后评估结果可重复。
- TCP 标定已经完成实测复核，或被明确列为阻止最终验收的未决项。
- V5 报告、已知限制和复现实行命令齐全。

## 14. 全程风险清单

| 风险 | 发现阶段 | 关闭条件 |
|---|---|---|
| TCP 平移偏置仅为第一版近似值 | S0/B | 实测标定并更新单一参数与回归测试 |
| USD 内部引用或碰撞 schema 随迁移失效 | A | 静态场景和接触检查均通过 |
| Jacobian body id、固定基座索引或关节顺序错误 | A/C | 解析记录、单轴动作和维度测试通过 |
| 接触 tensor 环境/body 维解析错误 | B | 多环境定向碰撞测试通过 |
| 控制频率问题被误判为 IK 不收敛 | C | dt、decimation、动作保持诊断一致 |
| 执行器调参掩盖控制器问题 | C | 基线参数先验收，调参独立成批 |
| 课程阈值污染最终任务真值 | E | 配置分离和固定评估审计通过 |
| Checkpoint 与配置、种子不匹配 | D/E | 命名、快照、恢复和复现检查通过 |

只有阶段 E 的最终验收门禁全部满足，才可将该迁移标记为完成。
